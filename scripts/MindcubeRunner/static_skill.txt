GLOBAL RULES
Use the original ordered views, current option letters and the question's reference frame. Original Image 1 has view_index=0. Each RGB/depth pair shares its captioned original pixel grid. Interpret preview colors and validity with the shared depth legend.

Each view has an independent camera frame and relative scale. Raw Z, distances, depth colors and coordinates cannot be compared across views or converted to meters/world directions. Image-plane, viewpoint-rotation and cross-view relations rely on RGB, perspective, occlusion and the question's reference frame. Only the four supplied evidence tools are admissible when tools are enabled.

REFERENCE FRAME AND TARGET BINDING
Track camera position, facing direction and the requested object's relation separately. For explicit rotations at the SAME camera position, encode directions clockwise in quarter-turns: forward=0, right=1, behind=2, left=3. Combine the initial facing, stated turn and requested relative direction modulo 4, then identify the object in that resulting direction. A turn changes facing; the word behind adds a further half-turn relative to the new facing. Use the stated view rotations to locate that direction. Once this composition is resolved, do not reinterpret the wording or invent a compass layout without conflicting evidence.

Views taken around an object need not share a camera position. Do not apply the same-position rotation shortcut to them. Use stated viewing relations and shared visible anchors to establish their relative facing and positions. Keep one consistent mapping; a changed viewing hypothesis requires recomputing its dependent directions.

Bind the same target across views using visible features and context. An object outside the requested image can still be relevant through another view; visibility in that image is not the direction relation itself. For camera movement, compare confirmed common landmarks, perspective and occlusion in a stated image grid. Invented world positions or field of view are not observations. A legal option's presence does not supply missing scene evidence.

Resolve lookalikes before inferring motion: similar plain surfaces do not establish identity, and a cropped-out distinctive part does not establish a different object. Match visible parts, their junctions, occlusion boundaries and shared background anchors. Test the proposed correspondence against the other visible objects; do not choose the correspondence because it produces a preferred motion option.

Distinguish the observer's left/right from an object's intrinsic left/right. Establish their mapping from the stated viewpoint convention and visible anchors; do not switch conventions while choosing an option. For a turn, start from the requested camera's position and facing, apply the turn, then evaluate movement relative to the bound target. Image-plane shifts or apparent size changes alone do not distinguish camera translation from rotation or a focal-length change. Cross-view depth colors are independently normalized and cannot establish approaching, retreating or a forward component of motion.

CHOOSING EVIDENCE
Check the concrete support for the deciding target bindings, reference frame and relation before committing. A direct visual answer is valid when visible features and consistent directional relations support it. Merely calling a relation clear, choosing the more likely room layout, or repeating the same interpretation does not resolve contradictory target bindings or direction mappings.

When an unresolved target identity or location changes the answer and tools are enabled, submit a candidate query that can clarify that binding now. Such hints can help identify common landmarks in cross-view questions even though they do not estimate camera pose. Inspect unfiltered candidates first when exact category spelling is unknown; yield new hints for next-request inspection. Once a useful evidence gap is identified, take that executable action instead of extending speculative room layouts and then declaring the visual guess resolved.

Use local measurements when a same-view depth or surface-distance comparison can settle the question. Rotation and cross-view camera motion still require visual correspondences and a consistent reference frame; local depth is not a pose estimator. If no available tool can resolve the remaining issue, make the best supported visual choice without inventing geometry or repeating ineffective calls. Missing reliable measurement leaves the available visual evidence and its unresolved bindings unchanged.

Candidate categories are confirmed and question/option-relevant, but IDs and box_xyxy are incomplete location hints, not verified identities, object counts or mask quality. Empty candidates do not prove absence. Depth summary quantiles are [10%, 50%, 90%]; availability alone does not imply usable local depth.

Read delivered candidate lists and count, including fields in compact shared_data, before planning another query. Match result_id to EXECUTED CANDIDATE QUERIES for the completed query's view_index and category; these host records distinguish actual calls from proposed code. An empty list is an observed coverage limitation, not a missing response. Candidate queries read a fixed exposed catalog: repeating the same arguments cannot add hints, and filtering an empty unfiltered all-view result cannot reveal objects. An empty filtered or single-view query leaves only its unqueried scope open. If old evidence lacks a query record, leave its scope unknown rather than inventing arguments.

Pixel binding must match each target to its original RGB and view_index. Visible interior surfaces avoid silhouettes, gaps, occluders, invalid depth and background; a box center may miss the object. Coordinates use 0 <= x < width and 0 <= y < height, not memorized examples. Empty/invalid patches can cause a terminal tool-contract failure rather than a recoverable quality notice.

Interpret each depth color at its bound visible surface in that view. One surface's color does not establish the depth of every object in a compound option. Numerical comparisons use reliable returned values, not approximate numbers read from preview colors.

point_depth is local camera Z, not Euclidean camera distance. Same-view depth order needs both target surfaces; one Z or a view quantile cannot establish it. pair_point_distance is Euclidean distance between local median camera points: both endpoints must bind correctly, and comparisons to one reference share the same verified reference pixel. It is not object-center distance, minimum object gap, complete dimensions or Z difference; separate point_depth calls are not prerequisites.

Both measurements use 5x5 patches in per-view relative units. Nearby offsets -3, 0, +3 check stability; local relative depth range above 10% is edge_sampling, while insufficient_local_depth means missing usable local evidence. Outer status="ok" means execution success, not reliable data. data.status="unreliable" supplies no depth/distance; reason_code, reason, sample_stability and pair unreliable_endpoints explain rejection. Stable samples can still bind the wrong object. Missing or rejected values are not numerical evidence.

Compact evidence separates pending review/inspection from delivered history. Each group has source_tool, execution status, shared_data, data_keys and rows. Read each row as [sequence_index, result_id, *values]; data_keys names the values, which combine with shared_data to reconstruct the original data. The first two row items are metadata. Sequence indices preserve original observation order. Distinguish group execution status from data.status and reuse already supplied evidence.

OVERALL CONDITIONAL SEQUENCE
The current phase determines admissible actions. Inspect RGB/depth, check target and direction consistency, and reuse prompt evidence. In program phases, act on a useful unresolved evidence gap; new hints are yielded for next-request inspection before selecting measurement pixels from their boxes. Bound pixels support needed batched same-view measurements, with every new measurement (including unreliable notices) yielded for later review before answering. Repair preserves pending review and hint inspection. Only unreliable or visually misbound pixels need replacement; verified pair endpoints remain, and new samples need yield/review. Consistent deciding visual evidence can support a direct answer without tool calls. Final phases admit only supplied evidence and visual reasoning.
