## 2. 原 RGB＋深度图的输入合同

从首轮开始，每次模型请求均包含：

1. Image 1：该题官方原始 RGB，保留 JPEG 原始字节。
2. Image 2：由该图已发布的 MoGe2 深度和有效区域生成的 PNG，相同视野、分辨率和像素网格，`view_index=0`。

201 图均已具有相对深度和点图。渲染 PNG 不运行 MoGe2、不调用模型，也不补跑预计算。

沿用已核查的确定性显示方式：

- 有效区域内的深度按 2%–98% 分位线性映射为灰度，显示端截断极端值。
- 深色表示较近的相机深度，浅色表示较远；紫色表示无效区域。
- 显示只帮助识别深度趋势和取样位置。数值工具仍读取原始深度和点图，不读取灰度值。
- 相机深度 Z 与两点欧氏距离不同；灰度差不能代替三维点距。
- 深度图是同一原图的预测表示，不是第二个相机视角、米制标定或完整三维重建。

同一请求中的图像说明只出现一次。RGB 负责对象、部件、遮挡和语义绑定；深度图负责辅助远近判断、位置检查和选点。

后续轮有新测量时，在深度 PNG 的显示副本上叠加取点位置、5×5 区域和结果标识。该标注副本替代纯深度 PNG，每轮仍最多两张图片，不追加第三张标注图，也不累积历史图片。原 RGB、深度数组、有效区域和点图均不修改。底层纯深度 PNG 与标注来源保留在宿主证据中。

## 3. 首轮、后续轮与终结轮

每次请求重新组装当前题的完整小上下文，不追加历史消息。每题最多五个程序轮和一个 JSON 终结轮，允许提前提交答案。第六次请求固定为终结阶段；工具调用额度用尽或发生超额拒绝时，下一请求提前进入终结阶段，使用终结阶段的文本上限。

| 内容 | 首轮 | 第 2–5 程序轮 | 终结轮 |
|---|---|---|---|
| 官方原始 RGB | Image 1 | 同一 Image 1 | 同一 Image 1 |
| 对应深度图 | Image 2，纯深度 PNG | Image 2；有测量时为标注副本 | Image 2；有测量时为最新标注副本 |
| 官方完整题文 | 原样一次 | 原样一次 | 原样一次 |
| 静态 Skill | 完整短 Skill | 同一份完整 Skill | 同一份完整 Skill |
| 图像／几何说明 | 尺寸、坐标、深度显示、相对单位 | 相同简短说明 | 保留解释现有证据所需说明 |
| 工具接口 | 当前允许的接口 | 当前允许的接口 | 删除，工具关闭 |
| 有效观测 | 空 | 前序全部仍有效观测 | 全部仍有效的观测 |
| 工作便笺 | 空 | 最新一条，标为模型未验证判断 | 最新一条 |
| 错误／不可用状态 | 空 | 最新错误及必要不可用状态 | 必要的错误／不可用状态 |
| 输出合同 | Python 程序，取证或提交 | Python 程序，补充取证或提交 | 仅原生答案 JSON |

首轮顺序：

1. 完整官方题文。
2. 图像与几何合同，包含唯一的一段深度显示说明。
3. 静态 Skill。
4. 紧凑工具接口与准确的字典读取示例。
5. 当前阶段、包含当前请求的剩余请求／程序轮数、预留终结轮、已用／剩余工具和测量额度。
6. 当前输出合同。
7. Image 1 原始 RGB；Image 2 同视角深度 PNG，分别附短标签。

首轮不预装全部候选，不交付原始数组、掩码或 Intern 完整回执。按当前题文的允许范围查询候选；不得交付其他题文、其他类别或隐藏候选总数。

程序工具在 `ctx.tools` 下。返回值是普通字典，使用 `r["data"]["depth"]`、`r["result_id"]` 等准确字段；`ReturnAnswer` 与 `YieldObservations` 为全局控制函数，不能写成 `ctx.tools.ReturnAnswer` 或 `ctx.tools.YieldObservations`。输出合同给出完整取证、提交示例，要求一个闭合 Python 围栏，唯一顶层入口为 `def solve(ctx):`，由宿主调用一次。XML、解释文字、未闭合围栏和入口格式错误在执行前返回修正提示；控制函数命名错误同样不执行，使用剩余程序轮重新生成。其他 AST 安全违规终止该题，不改写或执行被拒代码。Omini 本地答案桥接接收整数、浮点或文本，不借用 VSI 的 option 容器。

新测量必须在下一次模型请求中被读取和复核。模型检查目标对应、采样表面、深度图位置、数值与 RGB 关系；同一程序内刚测量就提交的答案只作为暂定提议。第五程序轮的新测量由第六次终结请求复核。每轮清空程序变量，前序工具事实与结果 ID 继续交付。

上一轮完整程序、长篇解释和 thinking 内容不回填。宿主保存完整轨迹；模型只接收有限的工具事实、工作便笺和错误状态。

## 4. 静态 Skill 的职责

只准备一份短 Skill，所有题和阶段使用同一内容及哈希。建议不超过 1800 个英文字符。

策略包括：

- 读取完整问题，绑定对象、部件和参照，保留假设尺寸、方向、选项及回答要求。
- 明确任务所需的计数、排序、距离或比例，以及分子、分母和共同参照。
- 从 RGB 判断对象与可见表面，结合深度图查看远近趋势及无效区域，再选择数值取样位置。
- 避开背景、遮挡、边界和孔洞；框中心不自动代表对象表面。
- 区分相机深度与两点距离，使用一致的参照与问题要求的维度。
- 下一轮结合 RGB、深度显示及数值复核测量，再用于计算或判断；视觉与数值冲突时先检查对象和采样位置。
- 可见计数检查实例、部件、重复和题目范围，候选数只作线索。
- 未授权的完整尺寸、体积、尺度测量和交互问题保留原图推理，按证据记录为视觉估计或混合判断。
- 按原题要求提交原生数值或文本。

Skill 不包含轮数、Python 输出格式、Yield 指令或终结 JSON 指令；这些由当前阶段合同统一提供。

## 5. 上下文长度与反馈

| 项目 | 发送前硬上限 |
|---|---:|
| 静态 Skill | 1800 个英文字符 |
| 首轮全部消息文本 | 4000 字符 |
| 第 2–5 程序轮全部消息文本 | 每轮 6000 字符 |
| 终结轮全部消息文本 | 4500 字符 |
| 最新工作便笺 | 200 字符 |
| 单次请求图像 | 2 张 |
| 单题工具调用 | 8 次，其中数值测量最多 6 次 |

文本统计包括所有消息、图像标签、唯一深度说明和反馈。当前已核查的 501 题官方题文最长 206 字符，完整保留。

反馈保留真实结果 ID、工具名、坐标、原始数值、有效样本数及必要状态。单位、坐标约定、工具定义和相同元数据集中写一次。重复展示同一结果 ID 时去重；不同采样位置产生的结果不合并。模型便笺标为 `model_note_unverified`，不能替代工具事实。

额度在题内跨轮共享，不因新请求而重置。准入后的执行失败消耗工具／测量额度；参数签名绑定失败在准入前终止，保留失败工具收据。第七次测量或第九次工具调用在底层执行前被拒，记录单独的 `quota_denials` 与 attempted／rejected 计数，不增加已准入次数，也不生成虚构的工具结果 ID。宿主受控结束当前程序，将此前全部成功事实、结果 ID、采样标记及额度原因交付下一次终结请求。普通领域、置信度、工具合同和超时错误仍按原错误路径终止；可修正的 Python 运行错误保留成功测量的下一轮复核要求。

超限时先消除重复说明、重复结果展示和冗余状态字段。不得截断题文、改写数值、丢弃答案依赖证据或静默删除冲突／不可用状态。仍超限则暂停该题并保存明确原因，不发送超限请求。

字符上限不包括视觉 token，不能换算成未经核验的模型 token 上限。先导检查实际文本与视觉输入用量；`max_tokens` 是输出参数，也不证明 thinking 用量被同样限制。实际费用使用服务 usage 与统一账本核对。

## 6. 工具权限与输入隔离

第一版只复用逐题允许的候选、全图深度可用性、局部点深度和同视图点距。类别确认不等于掩码质量确认；米制、世界坐标、跨视角身份和对象掩码测量权限保持关闭。

类别由当前题文及题内选项独立确定允许范围，使用冻结的归一化规则；不发起在线类别提取请求，也不把合并题文交给求解器。

保留图像缓存的实际方法版本：43 图为 `external-perview/1`，158 图为 `external-perview/2-bounded-review`。区别在类别审核显示尺寸，原 RGB、深度及分割保持原分辨率。

参考答案、答案派生的 yes/no 分组、GT 几何和其他题目上下文均不进入在线请求、工具返回或 Skill。候选、工具不可用和错误状态显式记录。

## 7. 终态与官方评分

隔离宿主按固定 VADAR 提交 `56018ebc2ecf7a430fc94e64e80e2768b0931739` 评分：

- int，70 题：预测字符串执行 `int(pred)` 后精确匹配；不截断小数，也不将 `"3.0"` 自动改成 `"3"`。

## 8. 实现与启动条件

先完成 Ominirunner 的双层输入／缓存验证、确定性深度显示、阶段上下文、原生答案桥接、受限执行和隔离评分。零请求检查必须验证：

- 原图及逐题绑定、缓存字节和版本身份；RGB、深度与有效区域同网格。
- 深度 PNG 的源数组、有效区域、渲染版本和 PNG 哈希；标注副本的点位及父图身份。
- 每轮准确交付原 RGB 和深度显示，最多两图；图像说明不重复，文本长度不超过上限。
- 首轮／后续／终结阶段合同一致，新测量具有下一轮复核机会，终结轮工具关闭。
- 静态 Skill、模型、采样、工具、输入及源码身份固定，GT 和凭据不会进入请求。
- 官方评分解析、严格阈值边界及完整分母通过离线检查。

两组模型与请求参数一致：`qwen3.8-flash`、`enable_thinking=true`、`temperature=0`、seed 137、每请求 `max_tokens=8192`、服务等待 600 秒、单次 HTTP 尝试。核对实际 usage，不能假定 thinking token 被该参数同样限制。

固定此前预览的 12 题：15、28、38、0、3、31、2、21、33、10、81、106。另仅按公开绑定中的类型和题号，以 `SHA256('omni20:137:'+sample_id)` 排序新增 4 float、2 int、2 str：190、375、411、222、49、479、417、350。总共 7 float、5 int、8 str；答案派生的 yes/no 分组只在完成后的宿主评分中建立。两组各 20 个 episode；新版最多 `20 × (1 + 6) = 140` 个请求，由配置统一计算。此前最多 48 请求的实验保持原冻结身份与结果；新版启动使用独立目录和新冻结身份。

正式启动前合并主账本与历史独立账本，并去除镜像／origin 副本。CV3D pilot 和 dispatch 两份局部账本的嵌套 governor 来源已核实，仅将 category、context、usage、status 多重集合匹配的局部副本去重；未匹配项仍计数，保留双方 admission 前缀和去重收据。补计 MMSI service retry 的独立消费。新请求同时记入配置计算的本次上限与既有主账本，不建立新的独立 20000 次额度。启动需容纳新版 140 次及 MMSI、MindCube 的剩余上限；另记录已由其他会话启动的 CV3D 实际消费与剩余 policy cap。每个新请求读取合并消费，触及总额立即停止。未知响应或服务身份变化暂停新派发，不自动重试已完成或状态未知的请求。

深度或显示缺失时不静默切换成 RGB-only。记录具体状态并保留分母；缓存身份损坏需先解决输入问题，不能自动重算。本次已实施用户批准的协议修正并进行零模型请求检查；在线复测与全量执行独立记录。
