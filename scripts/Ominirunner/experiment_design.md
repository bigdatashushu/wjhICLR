## 2. 原 RGB＋深度图的输入合同

从首轮开始，每次模型请求均包含：

1. Image 1：该题官方原始 RGB，保留 JPEG 原始字节。
2. Image 2：由该图已发布的 MoGe2 深度和有效区域生成的 PNG，相同视野、分辨率和像素网格，`view_index=0`。

201 图均已具有相对深度和点图。渲染 PNG 不运行 MoGe2、不调用模型，也不补跑预计算。

沿用已核查的确定性显示方式：

- 有效区域内的深度按 2%–98% 分位线性映射为灰度，显示端截断极端值。
- 深色表示较近的相机深度，浅色表示较远；紫色表示无效区域。
- 显示只帮助识别深度趋势和取样位置。数值工具仍读取原始深度和点图，不读取灰度值。
- 相机深度 Z 与两点欧氏距离不同；灰度差不能代替三维点距。
- 深度图是同一原图的预测表示，不是第二个相机视角、米制标定或完整三维重建。

同一请求中的图像说明只出现一次。RGB 负责对象、部件、遮挡和语义绑定；深度图负责辅助远近判断、位置检查和选点。

后续轮在 RGB 和深度显示副本上叠加相同取点位置、5×5 区域和 M 编号。原始 JPEG 始终作为 Image 1；Image 2 为深度显示，Image 3 为 RGB 标点副本。待复核点追加原像素比例的 RGB 局部图，每页至多八个唯一位置并保留全局坐标和裁剪映射。原 RGB、深度数组、有效区域和点图均不修改。

每次请求重新组装当前题的完整小上下文，不追加历史消息。每题最多五个程序轮和一个 JSON 终结轮，允许提前提交答案。第六次请求固定为终结阶段；工具调用和数值测量次数不触发提前终结。

| 工具接口 | 当前允许的接口 | 当前允许的接口 | 删除，工具关闭 |
| 有效观测 | 空 | 全部测量事实及最近候选／摘要 | 预算内完整事实，最多八条测量 |

| 输出合同 | Python 程序，取证或提交 | Python 程序，补充取证或提交 | 仅原生答案 JSON |

首轮顺序：

1. 完整官方题文。
2. 图像与几何合同，包含唯一的一段深度显示说明。
3. 静态 Skill。
4. 紧凑工具接口与准确的字典读取示例。
5. 当前阶段、包含当前请求的剩余请求／程序轮数、预留终结轮、累计工具调用和测量次数，以及不设次数上限的说明。
6. 当前输出合同。
7. Image 1 原始 RGB；Image 2 同视角深度 PNG，分别附短标签。

首轮不预装全部候选，不交付原始数组、掩码或 Intern 完整回执。按当前题文的允许范围查询候选；不得交付其他题文、其他类别或隐藏候选总数。

程序工具在 `ctx.tools` 下。返回值是普通字典，使用 `r["data"]["depth"]`、`r["result_id"]` 等准确字段；`ReturnAnswer` 与 `YieldObservations` 为全局控制函数，不能写成 `ctx.tools.ReturnAnswer` 或 `ctx.tools.YieldObservations`。输出合同给出完整取证、提交示例，要求一个闭合 Python 围栏，唯一顶层入口为 `def solve(ctx):`，由宿主调用一次。XML、解释文字、未闭合围栏和入口格式错误在执行前返回修正提示；控制函数命名错误同样不执行，使用剩余程序轮重新生成。其他 AST 安全违规终止该题，不改写或执行被拒代码。Omini 本地答案桥接接收整数、浮点或文本，不借用 VSI 的 option 容器。

程序轮只展示 Python 输出方式和第一条字面量复核赋值；终结轮只展示 JSON 输出方式和同名复核字段。复核判断、原始样本说明和完整证据结构仍从首轮开始交付，不按是否已有测量延后展示。提交示例带 visual_estimate 证据，因此在已有历史测量时也合法。阶段、次数、档案和图片标签缩短，几何用途及完整尺寸定义集中在证据协议。

新测量只能从下一次模型请求开始复核并支持计算。模型检查目标对应、采样表面、深度图位置、数值与 RGB 关系；同程序新测量不能通过计算证据验收。第五程序轮的测量可在第六次终结请求中复核。每轮清空程序变量，程序轮交付全部测量事实，终结轮按文本预算装配；保留数值精度和原始 ID。

`point_depth` 返回 `pixel_xy`、该实际中心的原始相机 Z `depth` 和逐点矩阵 `depth_samples={origin_xy,values}`。矩阵按行排列，保留原始精度，无效点用 null，图像边界按实际范围裁剪；不求均值或中位数。只有一个有效邻点时仍交付，整个邻域无效才按置信度失败处理。`pair_point_distance` 返回实际 a/b 中心的原始三维点距及各自深度矩阵，不对三维点做邻域聚合；任一中心的深度／三维点无效则 distance=null，更换端点需重新调用。输入坐标取整并限制到图内，返回和标图使用同一实际坐标。

同一个作答模型查看 RGB 标点、局部图和原始样本，只提交 `measurement_reviews = [{"result_id":"FULL_ID","decision":"usable"}]`。能辨认目标深度值为 usable；两点距离要求两个中心端点都在题目要求的表面上。测错目标为 resample，看不清为 uncertain。工具说明简短提示：边缘附近可能测到其他表面而使样本差异较大，模型自行辨认目标值；边缘本身不触发拒绝。不要求理由、对象或表面描述。程序中使用 solve 内第一条字面量赋值，终结轮使用 JSON 同名字段。只接受当前可见的成功测量；候选、摘要、未知或重复 ID 按条反馈，不影响其他合法记录。局部有效点数保留在工具回执，不额外重复邻域分位诊断。

模型在 thinking 中发现的错点需要正式记录；thinking 不自动解析为复核状态。每轮保存完整 `measurement_review_state`，最终保存 `measurement_reviews`；合法结论在该程序后续运行出错或下一轮格式出错时仍保留。可见事实附当前判断，补充摘要只含未展示的 resample/uncertain，至多 32 条 M 编号；数量与完整状态哈希留在回执，不重复展示可见结论和 usable 历史。旧 ID 可改判；当前 resample、uncertain 和未复核测量不能支持 calculation。

测量用途在最终计算绑定声明。point_depth 只能代表 camera_z，默认取原始中心值；可加 `sample_xy=[x,y]` 选择该测量已交付矩阵中的有效像素。宿主验证坐标及原始值，不自动选择深度簇。两点距离可绑定为 chord，不接受 sample_xy；替换端点必须重新测量。完整 height/width/length 的绑定另含 `geometry`：coverage、axis、anchors、objects。要求 complete 范围，对应 object_vertical／object_horizontal／object_length 轴向及 top/base、left/right、front/back 端点；objects 按 a/b 顺序声明同一对象，名称各限 80 字符。partial、unknown、轴向不符、不同对象或内部端点不能支持完整尺寸计算。这些是模型的语义声明，宿主验证结构和一致性。

证据装配先选择已声明的计算依赖，再选择 Yield 指定的待复核点和该轮新测量（最近优先），随后是可用测量、旧待办、拒绝测量及最近的候选／摘要。旧待办不会挤掉已有尺度参照。失败答案中引用的已知测量也保留为依赖；最近声明优先。每轮和最终结果保存 calculation_dependency_ids，审计重建同一状态。重复 ID 去重；程序轮保留全部测量记录，终结轮最多八条，局部图最多两页。终结轮受预算限制仍未展示的依赖明确标出。完整历史留在宿主，可见和遗漏数量、ID、事实及档案哈希进入回执。程序与终结轮沿用同一排序；无关待办不会阻止答案。

上一轮完整程序、长篇解释和 thinking 内容不回填。宿主保存完整轨迹；模型只接收有限的工具事实、工作便笺和错误状态。

## 4. 静态 Skill 的职责

只准备一份短 Skill，所有题和阶段使用同一内容及哈希。建议不超过 1800 个英文字符。

静态 Skill 按六步指导取证顺序：

1. 读题和 RGB，明确目标、共同参照、任务量、计数范围和给定尺度；视觉问题已明确时直接作答。
2. 工具开放时按需定位：目标不清楚时查 `view_candidates`，深度有效性有疑问时查 `view_depth_summary`。候选框不直接证明计数或缺失。
3. 工具开放且有需要时测量目标表面，比较时使用共同参照。RGB 核对候选框中心，辨认目标样本与背景／遮挡物；工具含义集中在接口与证据说明。
4. 下一请求先看 RGB 标点／局部图和逐点值并正式提交简短复核；工具仍开放时再补采样。错点与不确定值排除，只替换未解决的点。小差值时换代表点检查并再次复核。
5. 只使用当前可见、usable 且与任务量匹配的数值。给定尺度绑定完整跨度；统一计数／体积的对象范围和形状假设，note 保持待查性质。完整尺寸条件集中在证据协议。
6. 证据够用即停止。工具驱动的数值答案声明 calculation 和测量绑定，保留中间精度；几何未解决时回到 RGB 估计，禁用错点／未复核数值，保持答案与假设一致并使用简短依据。

Skill 不包含轮数、Python 输出格式、Yield 指令或终结 JSON 指令；这些由当前阶段合同统一提供。

程序轮超过 10000 字符时仍发送完整上下文，回执记录 text_over_threshold 与 text_over_threshold_chars，episode 汇总记录超阈值轮次。终结轮按原有预算装配，不截断题文、改写数值或静默删除依赖。原始 output／thinking 保存在逐轮 JSON，汇总 trajectories.json 同时列出超阈值请求。

字符上限不包括视觉 token，不能换算成未经核验的模型 token 上限。先导检查实际文本与视觉输入用量；`max_tokens` 是输出参数，也不证明 thinking 用量被同样限制。实际费用使用服务 usage 与统一账本核对。

## 7. 终态与官方评分

终结轮关闭工具，接受原生标量 answer、可选 measurement_reviews 和 evidence；直答组仍只接受 `{"answer": ...}`。有测量后必须声明视觉估计及短依据，或数值计算的表达式与绑定；无测量时可省略 evidence。数值不附加单位，文本不转换为字母选项。

## 8. 实现与启动条件

先完成 Ominirunner 的双层输入／缓存验证、确定性深度显示、阶段上下文、原生答案桥接、受限执行和隔离评分。零请求检查必须验证：

- 原图及逐题绑定、缓存字节和版本身份；RGB、深度与有效区域同网格。
- 深度 PNG 的源数组、有效区域、渲染版本和 PNG 哈希；标注副本的点位及父图身份。
- 每轮准确交付原 RGB 和深度显示；RGB/深度标点和局部图映射一致，程序轮超阈值记录准确，终结轮不超过上限。
- 首轮／后续／终结阶段合同一致，新测量具有下一轮复核机会，终结轮工具关闭。
- 静态 Skill、模型、采样、工具、输入及源码身份固定，GT 和凭据不会进入请求。
