# 系统现状 0924

> 扫描时间：2026-09-23。扫描范围：`skill3d_codebase/`。本报告只描述代码、配置、测试入口和系统现状；所有 Markdown 文件不纳入目录树，`data/` 下的数据集、帧、数组、trace 与实验产物不逐文件展开。

## 结论

这是一个 Python 3.11+ 的 Skill3D 研究型 3D 空间感知系统。当前主线已经迁移到 `src/skill3d`，旧版实现保留在 `legacy/`，VGGT 等外部依赖保留在 `third_party/`。系统有两条主流程：

- 在线推理：输入多帧视频/图像，经过输入门、VGGT 重建、质量/证据门、题型分类、Skill 检索、Qwen3-VL 程序合成、AST 检查、受限沙箱、几何裁判、MCA/MRA 评测和 trace 落盘。
- 离线演进：读取在线 trace，归纳候选 Skill，做泄漏检查、静态检查、分级 panel、诊断/修订和 promote/reject/quarantine；离线模型不能进入在线链。

当前状态是“研究管线已形成，但环境和实验复现仍未收敛”：

- `pytest -q` 未能完成收集。当前环境为 Python 3.12.4、NumPy 1.26.4、SciPy 1.18.0；SciPy 导入 `cKDTree` 时访问不存在的 `numpy.long`，导致 16 个测试模块在收集阶段报错。
- 工作树位于 `master`，有 20 个已修改文件和 3 个未跟踪文件，主要集中在 V7 在线链、重建门、sandbox、schema、分割、合成和工具代码。
- 已有 V7 C1 seed 0 的 `inner_validation` 结果：128 episodes，accuracy/MCA `0.296875`，MRA `0.5109375`；这是单 seed、inner split 结果，不能当作 outer/final 或多 seed 结论。
- 真实运行依赖外部 VSI-Bench、VGGT 权重、Qwen/vLLM、GroundingDINO、SAM2 和 GPU。manifest 中 Docker digest、checkpoint hash、MLflow run id 等仍是 unknown。
- `data/` 约 52 GiB，主要是 v5/v6/v7 实验产物、重建数组、图像帧和日志，不是源码目录。本报告只概括它，不把数据集内容写入模型上下文。

## legacy 与 third_party

- `legacy/`：旧版 `skill3d` agent、工具、Skill 学习、外部专家适配、训练脚本、旧评测和检查点目录。它包含 Depth Anything、GroundingDINO、OrientAnything、Pi3、SAM3、SwinIR 等历史集成，体量约 50 MB；不参与新系统 pytest 收集，也不属于默认在线链。
- `third_party/vggt/`：VGGT 的 vendored 源码和训练/可视化工具，约 230 个非 Markdown 文件；主系统通过 `reconstruction/vggt_runner.py` 调用其能力。其示例视频和训练资源不应写入模型上下文。

## data 目录摘要

`data/` 不进入逐文件目录树。当前约 52 GiB，包含：

- `reconstructions/`：VGGT、mock_light、real_e2e、real_test、历史重建数组、深度、相机、点云、mask 和帧。
- `traces/`、`traces_real/`：episode、program、geometry、evaluation、memory 和 trace record 的 JSONL。
- `v5_*`、`v6_*`、`v7_*`：各版本 smoke、calibration、scoped、inner 和 full 实验结果。
- `memory_episodic/`、`vsi_bench_meta/`、`checkpoints/`：在线记忆、数据集元信息和本地权重/检查点目录。
- 根部 `run_manifest*.json`、`readiness_manifest.json`：运行环境、配置 hash 和 readiness 记录。

数据状态只能证明“本机存在历史运行产物”，不能自动证明当前未提交代码与这些产物完全一致。

## 当前已知问题

1. **依赖环境阻塞测试。** `numpy==1.26.4` 与 `scipy==1.18.0` 不兼容，当前 `pytest -q` 在导入阶段失败；需要先统一 Python/NumPy/SciPy 版本，再重新执行测试。
2. **依赖声明不完整。** `online/config.py` 使用 YAML 读取能力，但 `pyproject.toml` 未显式声明 PyYAML。
3. **阈值尚未定标。** admission、质量门、恢复、sandbox 超时和检测器阈值中仍有 `TODO_CALIBRATE`。
4. **真实服务未由仓库自包含。** VSI-Bench 视频、VGGT 权重、Qwen/vLLM、检测器、SAM2、GPU 和 Docker 服务需要外部准备。
5. **复现元数据不完整。** V7 manifest 的 Docker digest、checkpoint hash、MLflow run id 等字段为 unknown，且 manifest commit 对应的是已提交 commit，不涵盖当前工作树修改。
6. **实验目录口径不一致。** V7 脚本目标为 `data/v7_inner128`，现有可见结果主要为 `data/v7_full/c1_seed0` 与 `data/v7_run/c1_seed0`，需要在正式报告中明确实际运行目录和 seed 覆盖。
