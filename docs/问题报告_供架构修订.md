## 0. 一句话摘要

架构文档在**模块划分、硬约束与状态机**层面与实现吻合度高（这条主干没有返工）；
但在三类地方出现了必须修订的偏差：

1. **输入契约缺失**：文档没有定义"多模态输入怎么进模型""帧分辨率在哪一层统一""VLM 框提示的协议与坐标空间"，这些空白在真实运行中直接变成了错误答案（最严重的是 **M8 从未把帧送进模型**）；
2. **阈值脱离真实数据**：文档 §10 的起始阈值（尤其 G1 的 `σ²<100`）若照抄进论文，与真实 VSI-Bench 视频相差近一个数量级；
3. **资源约束与阶段表的矛盾**：§11.3 假设"阶段串行复用 GPU"，但真实链路里 M3(VGGT) 与 M8(vLLM) 必须同时在位，同卡必然 OOM。

## 2. 逐条详述

### A. 环境与资源

**A-1｜`skill3d` env 的 vLLM 版本不可用**
本机存在名为 `skill3d` 的 conda env（疑似为本项目准备），但其 vLLM 为 **0.6.6.post1**，不支持 Qwen3-VL（需 ≥0.11）。若按环境名直觉使用会直接失败。
→ **文档建议**：§13.1 除"vLLM ≥0.11.0"外，补一句"使用前先 `python -c "import vllm; print(vllm.__version__)"` 核验；本机可用环境为 `qwen3`(0.19.1)/`wangjh`(0.11.0)，项目冻结环境为 `skill3d-exp`"。

**A-2｜BF16 权重装不下（实测）**
`Qwen3-VL-8B-Instruct` BF16 = 4 分片 16.3GiB；24GB 卡在他人占用 4.5GB 时加载即 OOM：
```
torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 144.00 MiB.
GPU 0 ... 59.44 MiB free. Process 1702760 has 4.46 GiB. This process has 19.02 GiB.
```
改用官方 `Qwen3-VL-8B-Instruct-FP8`（9.87GiB）后正常。
→ **文档建议**：§11.2 的"BF16 17.54GB 单卡不推荐"应升级为**硬性结论**："BF16 在本机（24GB 卡 + 他人共用）不可用，主线固定 FP8"；并把 §13.1 示例命令的默认模型改为 FP8。

**A-3｜32 帧需要放宽 prompt 图像上限**
默认 `--limit-mm-per-prompt` 为 4 张，§1.2 要求 32 帧均匀采样 → vLLM 直接 400：
```
At most 4 image(s) may be provided in one prompt.
```
→ **文档建议**：§13.1 与 §4 M8 补参数 `--limit-mm-per-prompt '{"image":32,"video":1}'`，并说明"该值必须 ≥ n_frames，否则服务端直接拒绝"。

**A-4｜`--max-pixels` 实测标定（替换 TODO_CALIBRATE）**
不限制时 32 帧 ≈ 32k+ tokens（挤爆 32k 上下文）。实测 `max_pixels=131072`：

| 输入 | prompt_tokens | 延迟（单卡 FP8） |
|---|---|---|
| 4 帧 | 1,246 | 0.9s |
| **32 帧** | **9,703**（≈303/帧） | **1.4s** |

KV cache 实测：`gpu_memory_utilization=0.77` → 7.53GiB → 54,848 tokens（32k 上下文并发 1.67×）。
→ **文档建议**：§15.2 的 `--max-pixels` 从 TODO_CALIBRATE 改为起点实测值 131072，并注明"32 帧 ≈ 9.7k tokens"。

**A-5｜VGGT 源码缺失（权重在）**
权重 `/home/cvailab/.cache/huggingface/geothinker/VGGT-1B/model.safetensors`（4.7GB）已在，但**任何 env 都没有 `vggt` 包**。已 clone 到 `third_party/vggt`。
→ **文档建议**：§4 M3 字段 12 区分"权重"与"源码"两项 TODO；§15.1 待输入清单同步拆分。

**A-6｜SAM2 档位需改**
本机只有 `sam2.1_hiera_large.pt`（856MB）与 `sam2_hiera_base_plus.pt`（309MB），**Tiny 未下载**。实测加载峰值显存：Large 0.98GiB / Base+ 0.44GiB（仅权重）。
→ **文档建议**：G-19 的"首选 Tiny"改为"首选 Large（本机可得），Base+ 为低显存备选"。

**A-7｜SAM2 config 必须用相对路径**
传绝对路径报 `MissingConfigException: Cannot find primary config 'home/cvailab/...'`（hydra 以 `sam2/configs` 为搜索根，且会吃掉前导 `/`）。
→ **文档建议**：§4 M5 字段 5 补"SAM2 config 用 `configs/sam2.1/sam2.1_hiera_l.yaml` 这类相对形式"。

**A-8｜COLMAP CLI 缺失（未解决）**
OS 无 `colmap` 可执行文件（`pycolmap` 4.2.0 已装，可读写模型）。影响：G-15 的 SfM 路径、以及 G-13 的完整 BA（`demo_colmap.py --use_ba`）跑不了；当前只做了"前馈 BA"（`pose_encoding_to_extri_intri`）。
→ **文档建议**：§7.1 G-13/G-15 标注"pycolmap 可读写；完整 SfM/BA 另需 COLMAP CLI"。

**A-9｜vLLM 与 VGGT/SAM2 必须分卡（实测 OOM）**
同卡布局（vLLM 18.9GB + SAM2）加载 SAM2 时报 `PositionEmbeddingSine ... CUDA out of memory`。改为"vLLM 占 GPU3、M1/M3/M5 占 GPU2"后正常。
→ **文档建议**：§11.3 阶段表补一行约束："**M3/M5 与 M8 服务不得同卡**；P1 重建与 P2 在线评测在 GPU 上分离（或 M3 完成后释放显存）"。这与 §3.1"阶段串行复用 GPU"并不矛盾，但需要写明"在线推理服务在评测期常驻，故重建需另卡或先释放"。

### B. 设计缺口与契约（影响论文口径，最需要修订文档）

**B-1｜M8 从未把帧送进模型（最严重）**
文档 §4 M8 字段 7 的伪代码只有 `render_jinja(...question, scene_summary, tools, skills)` —— 全是文本。实现照此写成"纯文本 prompt + 让模型编排 Tool"，结果是：**在线 VLM 看不到视频**，只能凭题型与工具文档猜程序。实测该 episode 生成的是：
```python
count = 0
if exists_in_scene("table"): count += 1
...
ReturnAnswer(count)
```
模型完全没有机会"看"房间。
→ **文档建议**：§4 M8 必须补"输入是多模态 messages（文本 + n_frames 张 JPEG）"，并在 §9.3 闭环时序里体现"帧 → Synthesizer"。这直接关系创新主张的成立性（code-as-action 的前提是模型能看现场）。已按此实现：`prompt_builder.build_image_messages`。

**B-2｜M8 消息格式**
`client.chat(prompt)` 把字符串当 `messages` 传 → `400 ... 'type': 'list_type', 'loc': ('body','message...`。
→ **文档建议**：§4 M8 字段 7 写明 `messages=[{"role":"user","content":[{...text...},{...image_url...}]}]` 的结构。

**B-3｜G1 阈值脱离真实数据（论文数字风险）**
实测 32 帧均匀采样的 Laplacian 方差：

| 数据集 | min | 中位 | max |
|---|---|---|---|
| arkitscenes | 1.5 | **39.1** | 100.9 |
| scannet | 9.6 | **49.7** | 264.5 |
| scannetpp | 57.8 | **315.3** | 941.2 |

文档 §10 的起始阈值 `σ²<100 记模糊` 会把 arkitscenes/scannet 的**几乎所有正常帧**判为模糊（实测一条真实 episode：31/32 帧被判劣化）。跨数据集相差近 10 倍，单一绝对阈值不可用。
→ **文档建议**：§10 G1 改为"绝对下界（≤10）+ 相对本 episode 中位×0.35"的双判据，并把上表作为标定证据写进论文附录；§15.2 的对应条目从 TODO 改为"已起始标定，仍需在完整 split 上复核"。

**B-4｜MRA 口径需澄清（未决）**
文档 §10 写 `rel=|gt-pred|/max(|gt|,1)`，对 θ∈{0.50…0.95} 逐阈值算 `(rel≤θ)` 再平均。实现严格照此（`evaluation/mra.py`）。但由此得出：**rel=0.5 时全部 10 个阈值都通过 → MRA=1.0**。即"50% 相对误差"在 MRA 上是满分。实测该 episode（答案 1 vs GT 2，rel=0.5）正是 MRA=1.0。
→ **文档建议**：这是**需要与官方代码二次核对的口径问题**，不能只照文档字面实现。若官方确为"θ 越大越宽松"，则论文中应明确 MRA 的宽松性并同时报告 MCA 与分段误差，避免审稿人误读。已在 §15.2 标为待核。

**B-5/B-6｜题型分类与 MCA/NA 分流**
实现原用非官方短名（`relative_direction`/`route_plan`/`absolute_distance`…），真实 meta 的 10 个取值有 **9 个直接抛 `UnknownQuestionTypeError`**；且 `object_counting`（无 options）与 `object_rel_distance`（有 options）的 MCA/NA 判定是反的。
官方 10 取值 → 8 规范题型的映射与"4 MCA + 4 NA"的实际归属已在代码与测试中固化。
→ **文档建议**：§1.2 与 §4 M7 补一张"官方 question_type ↔ 规范题型 ↔ 作答形式"的对照表（含 `object_rel_direction` 的 easy/medium/hard 三档）；§16.1 主表的"8 任务分别准确率"按规范题型聚合。

### D. 需要架构决策的问题

**D-1｜M5 框提示协议未定义**
文档只说"在线 Qwen3-VL-8B 给对象名 + bbox 提示"，但未定义：给多少帧的提示？坐标空间是什么？同一物体在多帧被重复提示怎么去重？实测把"整帧当框"的退化实现喂给 SAM2，等于分割整幅图。
→ **建议在 §4 M5 字段 6/7 增补协议**：
1. 每 episode 探测 K=4 帧（0、n/3、2n/3、n−1）；
2. 提示坐标统一用 **0–1000 归一化整数**（模型天然输出，且与分辨率解耦），由客户端换算到像素；
3. 每个 (帧, 框) 分配独立 obj_id，SAM2 从该帧起传播；
4. 传播后按**世界质心**去重（阈值 = 场景深度中位 × 0.15），保留置信度更高者。

**D-2｜尺度置信档恒为 low（影响 measurement 主结果）**
实测仅地平面锚点时 `scale_confidence=low`、`scale_ci≈3.4m`，于是 G-11 门控把 measurement 题全部降级 2D-only。文档 G-11 验收写的是"**无标准物体时**降级并标 low"，但没定义"只有地平面、没有标准物体"这一**默认路径**算不算"无标准物体"——而实测这条路径就是默认路径。
→ **建议**：明确 G-11 的档位判据与默认预期。若接受"无 SAM2 对象锚点即 low"，则需在论文中说明 measurement 题的覆盖依赖对象锚点；若要求默认可达 medium，则需放宽 CI 门或引入更多锚点来源（例如平面尺寸先验）。**这是会影响主表数字的决策，需要你定。**

**D-3｜Tool 在产物缺失时静默返回 false（静默错答风险）**
实测 `route=fallback_2d_only`（可用产物仅 `{frames, intrinsics}`）时，M8 生成的 program 仍调用了需要 `objects` 的 `exists_in_scene`，Tool **没有报错**而是返回 `false`，最终给出"0 张桌子"这一**看起来合法但完全错误**的答案，并被当作正常作答记入 MRA。
→ **建议（需架构决策，二选一）**：
- (a) 按 route 裁剪 M8 prompt 中暴露的 Tool 文档（硬约束 17 的延伸），使模型只能编排当前可用 Tool；
- (b) Tool 在所需产物缺失时**抛确定性异常**，由 M10/M11 归因到 `tool_contract` 失败，而不是返回布尔假值。
建议同时做 (a)+(b)：前者防患于未然，后者兜底防静默错答。**当前两者都未实现**，这是我认为对"答案可信度"威胁最大的一条。

**D-4｜M3/M5 与 M8 同卡 OOM**
同 A-9。文档 §11.3 阶段表需补"在线推理服务常驻期间的显存预算"，否则实验无法稳定复现。

**D-5｜M4 日志打印占位值**
runner 打印 `art.quality.overall_quality`（artifact 里是 NaN 占位），而门禁实算值在 `SceneState.summary` 里。日志显示 `overall_quality=nan` 易被误读为"质量门禁失效"。
→ **建议**：文档 §4 M4 字段 7 的伪代码保持 `q.overall_quality`；实现侧改为打印门禁实算值（待修）。

**D-6｜M2 丢帧后与 32 帧 artifact 失配（潜在，未验证）**
`input_gate` 返回 `drop_and_refill` 时，runner 会从 `pixels` 中删除劣化帧；但重建产物（尤其"P1 批量重建 + P2 复用 artifact"流程）仍是 32 帧。此后 M5 的 mask 帧索引与 artifact 的帧索引将**指向不同物理帧**。触发条件：劣化帧占比 > `TH_DEGRADED_RATIO`(0.25)。
→ **建议**：文档 §4 M2 字段 9 与 §4 M4 需定义"丢帧后如何与重建帧对齐"（例如：丢帧仅打权重不删帧，或重建阶段使用同一份保留帧列表）。**本 episode 因 4/32 < 0.25 未触发，故未验证。**

### E. 统计与复现

**E-1｜golden 数值与环境绑定**
同一份代码，两套环境的 paired 统计不同：base 环境 `wilcoxon p=0.3711`，冻结环境 `p=0.5000`（scipy 1.26 → 1.16）。golden 夹具必须与冻结环境绑定。
→ **已处理**：`golden_stats.json` 记录 `env_versions`，环境不符时该测试跳过。
→ **文档建议**：§16.4 复现 checklist 补"golden/统计基线须记录 scipy/numpy 版本，环境不符即视为不可比"。

**E-2｜零方差组的 p 值语义**
scipy 1.16 对完全相同的两组返回 `p=nan`（旧版返回接近 1）。nan 会被误当作"未计算"流入论文表格。
→ **已处理**：统计模块把非有限 p 归一化为 `None` 并加注"退化样本 → 判为不显著"。
→ **文档建议**：§16.3 统计检验表补一行"退化样本（零方差/完全相同）的处理约定"。

**E-3｜RunManifest 需记录影响结果的推理参数**
`max_pixels`/`n_frames`/图像上限会实质改变结果，但 §16.4 的 checklist 未列。
→ **已处理**：RunManifest 增补 `vllm_model / n_frames / max_pixels / max_model_len / vllm_endpoints`。
→ **文档建议**：§16.4 checklist 同步。
