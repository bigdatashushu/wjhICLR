## 2. 模块级落点

### M3 重建 + 尺度支路（§3 M3 v4）
- **尺度与 BA 解耦**：`ba_route` 不参与尺度；`anchor_metric_scale` 只做锚点提取，
  v4 的融合/校准/授权全部在 `scale_assessment.assess_scale`（唯一入口）。
- **多锚点**：`ground_plane_anchor`（地平面 RANSAC + 相机高先验）与 `object_anchor`
  （门/桌/椅等 `OBJECT_SIZE_PRIORS`，先验均标 `TODO_CALIBRATE`）→ `fuse_scale_anchors_robust`。
  融合在 **log 尺度空间**：先「共识窗口」（票数优先、权重和破平）选多数派，再在
  共识集内做 Huber IRLS 精修；CI = 1.96 × 加权 MAD / √n_eff，并与各锚点自身
  `rel_sigma` 取较大者（地板，防单锚点 CI=0 的过度自信）。
- **冲突检测（两路，任一成立即 `scale_conflict=True`）**：被拒锚点权重占比 >
  `CONFLICT_WEIGHT_FRACTION(0.4)`；或接受集内部尺度比 > `ANCHOR_CONFLICT_RATIO(1.5)`
  且被拒权重非零。冲突幅度并入 CI（区间必须覆盖冲突另一侧）。
  单个小权重离群锚点只标 `reason_code="outlier"`，**不误报冲突**（§10.2 L1）。
- **零重算与写回**：`apply_scale_assessment` 写 artifact 前先 `assert_ci_consistent`（生产端
  保证），schema 校验器只做消费端兜底降级（不抛异常，避免旧数据让整链不可用）。

### M4 质量门禁 + SceneState（§3 M4 v4）
- `route` **仍只由质量决定**（`route_from_quality`，fail-closed 未变）；
- 尺度另走逐题通道：`quality_gate` 把 `allowed_metric_tasks` 从 artifact 派生进 `SceneState`，
  `scale_is_usable(..., allowed_metric_tasks=...)` 以授权集合为准（空集 = 米制不可用）；
- G11 输入改为 `scale_ci_rel`（分数口径），旧绝对字段仅作兼容回退。

### M6 Tool Registry（§3 M6 v4）
- `ToolSpec.supported_metric_tasks` 新增；注册期强制「声明了米制题型就必须依赖 `scale` 产物」；
- `call_tool` 顺序：`validate(args)` → **逐题授权**（`ConfidenceGateError`）→ 产物契约
  （`ArtifactUnavailableError`）→ 执行。授权失败归 `confidence_gate`，产物缺失归
  `tool_contract`，kernel 统一映射到 `tool_contract` 桶（§4.5）；
- `docs_header` 头部新增「允许的米制题型=…（当前题型=…）」，未授权时明确写「（无）」+「请勿用相对单位冒充米制」。

### M7 题型分类 + Skill 检索（§3 M7 v4）
- `metric_tasks_after_quality_gates`：`medium` 档的 `object_size_estimation` 需 G8/G9 同时达标，
  `room_size_estimation` 需覆盖/平面质量达标；**`high` 档不再叠加**（§10.2 已在标定期用更严门槛把关）；
- Skill 硬过滤 `metric_task_authorized(scene, task_type)`：米制 Skill 必须逐题型命中
  `allowed_metric_tasks`，不得只凭全局 `scale_known`/`scale_confidence` 放行。

### 在线 FSM（§5.1 v4）
`RECONSTRUCT → SCALE_ESTIMATE → SCALE_CALIBRATE → QUALITY_GATE`（新增两态）。
尺度失败**不中止** episode：只落 `low` + 收回米制题型 + 记 `scale_conflict`；
`RECONSTRUCT --skip--> QUALITY_GATE` 用于复用 artifact / mock_light（尺度已随 artifact 落盘）。

### §7 复现与报告
- `RunManifest` 新增 `scale_calibration_id / calibration_split_hash /
  excluded_vsibench_scene_hash / confidence_level / scale_confidence_distribution /
  allowed_metric_tasks_observed / readiness_manifest_ref`，由 `online/eval._scale_manifest_facts`
  从 outcomes + **冻结校准器自带的审计清单**填充（记录的是实际使用的那份校准器）；
- `evaluation/scale_report.py`：逐题型 MRA/refusal/coverage + 锚点触发率/接受率/冲突率 +
  名义 vs 经验覆盖 + 来源分布；**单列小节，不混主表**；检测到 mock/合成来源时强制写
  「只是管道验证，不可当结果」的 note。

### §10.2 PoC 阶梯
`reconstruction/scale_poc.py`：L0 口径单测 / L1 合成多锚点 / L2 标定规模消融
（`N∈{10,30,100}`，N=10 仅诊断）/ L3 真实 held-out 逐题型验收。缺真实数据时
**UNVERIFIED + 退出码 1**，不用合成数据冒充标定结果。CLI：
`python -m skill3d.reconstruction.scale_poc [--l2-records ...] [--l3-outcomes ...] [--out receipt.json]`。

### §10.1 BA PoC 实测结果：**未通过（显存否决）**

在 RTX 4090（24 GiB，卡 0 独占、VGGT 前向结束后先释放显存 free=22.97 GiB）上跑真实
VSI-Bench scene（`41125700`，诱导集，32 帧）：BA 执行路径**已跑通到 tracker 内部**，但
`predict_tracks` 显存不足 → 按规格回退 feed-forward。实测证据：

| 配置 | tracker 网格 | 帧数 | max_query_pts | fine_tracking | complete_non_vis | 峰值 |
|---|---|---|---|---|---|---|
| 真实 PoC（首次） | 518² | 32 | 2048 | True | True | OOM（要 10.50 GiB，free 5.72） |
| 真实 PoC（释放 VGGT 后） | 518² | 32 | 2048 | True | True | OOM（要 6.28 GiB，free **1.16**） |
| 合成分档 | 518² / 392² / 336² / 280² | 32 | 2048 | True | True | 全部 ~22.8 GiB |
| 合成分档 | 518² | 4 / 8 / 16 | 2048 | True | True | 22.7 / 22.9 / 22.8 GiB |
| 合成分档 | 518² | 32 | 2048 / 512 / 256 | True / False | True | 全部 ~22.9 GiB |
| 合成分档 | 518² | 8 | 1024 | True / False | **False** | 22.3 / 20.8 GiB |

结论：**峰值与输入规模无关（恒定 ~21–23 GiB）**，24 GiB 卡不可能容纳；
官方 demo 用 1024² 喂 tracker（比我们的 518² 更贵），说明官方流程面向更大显存的卡。
按 §10.1 否决标准，BA route 维持 `[Conditional Go]`、`real_poc_verified=false`；
代码按规格回退 feed-forward（`g5=None` + `depth_conf/point_conf` 弱代理，**未标 vggt_ba**）。

**下一步（需用户决策）**：① 在 ≥48 GiB 卡上复跑（A6000/6000 Ada/A100）；
② 或替换为更省显存的 tracker（如 SuperGlue/LightGlue 匹配 + pycolmap 三角化），
但那已偏离"官方 VGGSfM tracker"的既定路线，属规格修订。
