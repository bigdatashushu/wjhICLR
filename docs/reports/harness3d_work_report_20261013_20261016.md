## 三、重点成果

### 1. M4 重建质量门升级

原质量门主要依赖 warp 和点云重叠，无法充分识别“视图间看似一致，但深度头、点图或局部点云结构异常”的场景。本阶段将场景准入改为四项指标全部通过：[cite:1]

| 指标 | 判定方向 | 当前候选阈值 | 作用 |
|---|---:|---:|---|
| 跨视图 warp 内点率 | 越高越好 | `>= 0.50` | 检查跨帧几何一致性 |
| 分组点云重叠率 | 越高越好 | `>= 0.30` | 检查前后子云重叠 |
| 深度头与点图相对差 P95 | 越低越好 | `<= 0.15` | 检查两个几何输出头的一致性 |
| 点云邻域长尾比 P95/P50 | 越低越好 | `<= 3.0` | 检查局部点云是否出现异常长尾 |

同时完成以下工程约束：

- 质量版本升级为 `v7-scene-warp-overlap-head-tail`，与冻结几何数组分开版本管理。
- 旧 v6 质量记录可以读取，但不能直接授权 3D 路由；必须从原数组重算并生成新收据。
- 缺失、`NaN` 或非有限指标统一 fail closed，不把“无法计算”当作“通过”。
- 场景只保留一个统一判定，B01/B11 共用，不把质量门变化误解释为 Skill 收益。
- 原重建数组和历史产物哈希保持不变。

该提交的历史验证记录为：服务器 `1303 passed、2 skipped`，本地 `1301 passed、3 skipped`，核心 Pyright 0 错误/0 警告；冻结数组回放 32 个场景中 25 个通过，原产物哈希未变化。[cite:1]

需要注意，`0.15` 和 `3.0` 仍是候选阈值。25/32 的历史回放只证明实现可运行，不能代替独立场景标定，也不能与旧 `0c2a406` 冻结实验混合解释。

### 2. M5 语义可靠对象构建

#### 2.1 先完成问题定位

10 月 15 日的四题实测覆盖纸袋、冰箱、主机/暖气和椅子。GroundingDINO 产生 210 个 NMS 后候选，原流程形成 169 条对象记录，其中 96 条通过数据合同检查；人工复核仍发现至少 24 条明确语义错误。[cite:4]

典型问题包括：

- 白板擦、挂饰和白板被标为纸袋；
- 门、储物箱和打印机被标为冰箱；
- 柜体、显示器和暖气被标为电脑主机；
- 椅子、风扇和百叶窗被标为暖气。

该结果证明，mask、点云、文件哈希和可见帧检查只能验证数据完整性，不能证明对象类别正确。四题 B01/B11 的平均 MRA 分别为 0.450/0.325，也不支持当时的 M5 已带来答题收益。[cite:4]

逐帧对照进一步显示，SAM2 长轨迹会把单个对象传播到其他物体或背景。例如椅子点云最大跨度从长轨迹的 3.086 m 收缩到人工限定同实例帧后的约 0.88 m；210 对种子 mask 的逐帧/视频 API IoU 中位数为 0.9934，说明主要风险来自跨帧身份漂移，而不是种子帧分割本身。[cite:5]

#### 2.2 完成主路径改造

新的 M5 主路径按以下顺序执行：[cite:2]

1. Qwen3.8-Flash 从问题和选项中提取目标类别、角色和原文依据。
2. GroundingDINO 以 0.25 阈值扫描全部可读冻结帧，同帧同类别执行 0.7 NMS。
3. SAM2 使用 Image Predictor 做逐帧独立分割，同一帧只执行一次 `set_image`。
4. Qwen3.8-Flash 查看完整上下文框、原始 crop 和 mask overlay，在不知道目标类别的情况下描述实际对象。
5. 第二次纯文本请求只比较已冻结的观察类别与目标类别，输出 `match/mismatch/uncertain`。
6. 只有 `match`、可见、mask 纯净且覆盖完整对象或主要部分的候选，才能反投影生成点云。
7. 单帧候选使用 complete-link 和 3D 质心/包围盒约束保守合并，避免链式连接相邻实例。
8. 最终对象继续校验 mask、点云、bbox、质心、候选身份和语义收据。

该流程采用 fail-closed 策略：`mismatch`、`uncertain`、API 异常、JSON 合同错误或 mask 质量不足都不能生成可信对象点云，但不会被解释为“场景中不存在该对象”。

#### 2.3 定向验证结果

Qwen3.8-Flash 在 13 个从旧模型失败案例中挑选的定向样本上，两次运行的最终类别关系均为 13/13 正确；原 Qwen3-VL-8B 在同一组样本上为 6/13。[cite:6] 该样本是定向难例，不代表总体准确率。

纸袋题 2234 随后完成真实 Qwen3.8、GroundingDINO、GPU SAM2、点云生成和绑定验证闭环：[cite:7]

| 指标 | 结果 |
|---|---:|
| DINO 全帧请求 | 32 |
| NMS 后候选 | 24 |
| SAM2 编码帧 / mask | 22 / 24 |
| Qwen 请求 | 26 |
| 语义拒绝 / 准入候选 | 21 / 3 |
| 合并后对象 | 2 |
| 绑定验证通过对象 | 2 |

复用上一轮单人人工标注后，20 个明确负例全部被拒绝，2 个明确正例全部保留；2 个不确定样本中 1 个拒绝、1 个准入。该结果仅覆盖纸袋类，不能外推为全部类别指标。全部 210 候选、四题最终对象和答题效果仍需按新生产实现完成全量复测。

### 3. 全链路统一到百炼 Qwen3.8-Flash

在 M5 验证完成后，继续将 M8 程序生成和评测视觉补答从本地 Qwen3-VL-8B 切换到同一百炼客户端：[cite:3]

- 配置统一为 `configs/config.yaml` 的 `online_model`。
- M5 题目解析、mask 审核、M8 程序生成和视觉补答共用 `qwen3.8-flash`。
- 删除 `src/skill3d/synthesis/vllm_client.py`、本地 Qwen 配置和 `serve_qwen3vl_dp8.sh`。
- 启动链不再下载或启动 8B 权重，GPU 主要留给 VGGT、GroundingDINO 和 SAM2。
- API Key 仅在请求时从 `DASHSCOPE_API_KEY` 读取，异常消息会脱敏，密钥不进入配置、对象身份或收据。
- Trace 来源由 `vllm_*` 迁移为 `online_model_*`，同时保留旧收据兼容映射。
- 未固定模型 revision 时禁止跨运行磁盘缓存，避免云端别名更新后复用旧结果。

这项调整减少了一套本地模型服务、权重和 GPU 调度链，降低了部署复杂度。代价是在线链依赖百炼网络和 API 可用性，因此真实运行前必须完成密钥、网络、限流和 endpoint 检查。

## 五、阶段价值

- **3D 路由更保守。** 场景级几何质量不满足四项要求时，系统不再继续输出看似精确的 3D 结果。
- **对象污染更早被阻断。** 语义审核位于点云生成之前，错误检测不再先进入对象点云和几何工具。
- **跨帧漂移风险下降。** 主路径取消 32 帧双向长轨迹，逐帧候选的实例身份由显式 3D 规则控制。
- **证据链更完整。** 问题解析、检测、分割、视觉观察、类别关系、点云和绑定均保留版本与哈希收据。
- **部署更轻。** 在线多模态能力收敛到一个百炼模型，本地不再维护 8B VLM 服务和对应 GPU 资源。

## 六、风险与下一步

1. **M4 阈值尚未独立标定。** 需要在未参与阈值选择的场景上冻结校准方案，再决定正式阈值。
2. **M5 全类别验收未完成。** 需要按新生产代码重跑全部 210 候选，并复测四题对象数量、尺寸和最终答案。
3. **同类别多实例关联仍需验证。** complete-link 已避免链式合并，但尚未证明椅子等密集多实例计数达到可靠水平。
4. **真实 API 运行环境待补齐。** 当前 Mac 和服务器非交互会话均缺少 `DASHSCOPE_API_KEY`；密钥只能通过环境变量或密钥管理系统注入，不能写入 Git。
5. **云端网络与限流需专项验证。** 历史服务器直连百炼延迟较高，正式实验前应验证业务 Workspace endpoint、并发和失败重试。
6. **不能提前声称最终精度提升。** 当前证据支持工程可靠性改造和纸袋类小样本有效，但不支持宣称 VSI-Bench 总体准确率或 MRA 已提升。
